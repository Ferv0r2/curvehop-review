Curvehop 아키텍처

조사는 미리 끝내고, 요청에는
검증된 스냅샷만 내보낸다

Curvehop은 공고 한 건에서 그 회사의 사업과 조직, 지원 조건까지 이어 읽게 하는 서비스다. 자료를 모으고 해석하는 일은 느리고 불확실하다. 그래서 그 일을 비공개 배치로 밀어내고, 발행 관문을 통과한 자료만 main을 거쳐 공개 런타임에 싣는다.

  • 0요청 처리 중 부르는 모델, 수집기, Git
  • 0발행을 결정하는 모델 호출. 공개 여부는 스크립트가 정한다
  • 4미니PC가 자동 머지할 수 있는 data 파일. 나머지는 코드 PR로만 바뀐다
01 전체 구조

자료는 왼쪽에서 오른쪽으로 한 방향, 요청은 오른쪽 상자 안에서 끝난다

느린 일(수집, 조사, 검토)과 빠른 일(페이지 응답) 사이에는 main 머지 하나만 있다. 번호를 누르면 그 위치의 설계 판단으로 이동한다.

옆으로 밀어 전체 구성도를 볼 수 있다.

  • 스크립트 실행
  • 모델 호출
  • 발행 관문
  • 발행 권한 없는 평가
  • 파생본
  • 자료 흐름
  • 요청과 응답
  • 보조와 관측
02 설계 판단

다섯 가지 판단과 감수한 비용

항목에 마우스를 올리면 위 구성도에서 해당 부분만 남는다. 점선 테두리 경로는 운영 저장소에만 있다.

  1. 1

    요청 경로에 모델과 수집을 두지 않는다

    의도
    구직자가 읽는 속도와 화면의 정확도가 수집 실패나 모델 지연에 흔들리지 않아야 한다.
    판단
    미니PC가 정해진 시각에 수집과 조사, 검토를 끝내 두고 Worker는 배포에 포함된 JSON만 읽는다. KV, R2, D1 같은 저장소 바인딩도 두지 않았다.
    감수한 비용
    원문이 바뀌어도 다음 수집과 발행, 배포를 거쳐야 화면에 반영된다.

    lib/store.tswrangler.jsonctests/ssr-reads-http.test.mjs

  2. 2

    모델의 정상 종료는 발행 승인이 아니다

    의도
    그럴듯한 문장이 근거 없이 사실로 공개되는 일을 막는다.
    판단
    조사 후보와 원문 검토를 서로 다른 Codex 호출(읽기 전용, 하루 12회 상한)로 나누고, 공개 여부는 스크립트가 형식과 인용, 반영 영수증을 다시 계산해 정한다. 외부 평가 모델 JEV는 판정만 기록한다.
    감수한 비용
    호출과 지연이 늘고, 근거가 모자란 주제는 보류로 쌓인다. JEV의 0.75는 정확도가 아니다.

    lib/data-gate.tslib/research-publication.tslib/jev-shadow.tstests/data-gate.test.tstests/jev-shadow.test.ts

  3. 3

    데이터베이스 대신 Git의 JSON 파일

    의도
    자료와 코드를 같은 커밋으로 묶어 비교하고, 되돌리고, 배포된 내용을 확인한다.
    판단
    미니PC가 자동 머지할 수 있는 파일은 공고, 회사 조사, 회사 관계, 등록 출처 4개뿐이고 자료 갱신 PR은 검증한 커밋 그대로만 머지한다. 나머지 자료 JSON은 코드 PR로만 바뀐다. 원본과 실행 기록은 비공개 이력 저장소에 따로 백업한다.
    감수한 비용
    자료가 늘면 번들과 빌드가 커지고, 쓰기는 미니PC 한 곳에서만 한다. 자료 갱신이 곧 배포다. (2026-10-22 공고 1,647건)

    lib/deployment-data.tslib/worker.tsscripts/cloudflare.mjs

  4. 4

    공유 캐시에는 공개 자료만 넣는다

    의도
    다른 사람의 직무나 경력 조건이 내 목록에 섞이거나, 늦게 끝난 이전 읽기가 새 자료를 덮지 않게 한다.
    판단
    revisionCache는 같은 자료 버전의 공개 자료만 공유하고, 읽기 전후와 대기 뒤에 버전을 다시 확인한다. 쿠키 조건과 필터 결과는 요청마다 조합하고 북마크는 브라우저에 둔다.
    감수한 비용
    요청마다 조합 비용이 든다. isolate 단위 캐시라서 분산 일관성은 보장하지 않는다.

    lib/revision-cache.tslib/render-data.tslib/preference-store.tstests/revision-cache.test.ts

  5. 5

    배포 성공은 실서비스가 그 커밋을 내보내는지로 판정한다

    의도
    빌드가 통과해도 사용자 화면이 정상이라는 보장은 없다.
    판단
    workerd와 Chromium 검증을 거쳐 업로드하고, 실서비스 /api/release가 내보내는 커밋과 자료 해시를 기대값과 대조한다. 실패하면 이전 버전으로 되돌리고 다음 배포를 보류한다.
    감수한 비용
    배포 시간과 스크립트 복잡도가 늘어난다. GA 실제 수신과 유입은 따로 관측한다.

    scripts/cloudflare-builds.mjsscripts/cloudflare.mjsapp/api/release/route.tstests/analytics-deployment.test.ts

03 요청 흐름

같은 회사 자료를 읽어도, 두 사람의 조건은 섞이지 않는다

판단 4를 펼친 그림이다. 공유하는 것은 불변 스냅샷과 그 버전의 공개 자료뿐이고, 사람마다 다른 값은 요청 안에서 만들고 버린다.

이 그림의 범위와 확인 근거

아래 경로는 모두 운영 저장소 기준이며, 공개 검토판에는 없는 파일이 포함된다.

  • 2026년 10월 22일 오후의 운영 코드를 기준으로 그렸다. 공개판은 같은 날 오전 시점의 코드와 가상 자료를 쓰며, 지금의 운영 코드와 같다고 주장하지 않는다.
  • 스케줄은 scripts/minipc/install-cron: jobs 6시간마다(:17), research 10:00, publish 11:30, discover 일요일 13:30, watchdog 매시 :47.
  • 모델 호출은 codex exec --sandbox read-only(조사와 검토 각 1회, 하루 12회 상한 lib/model-call-budget.ts). JEV는 별도 외부 평가 API이며 publicationAuthority: false.
  • 자료 갱신 PR 머지 조건: GitGuardian 통과, 같은 커밋의 Cloudflare 검증 통과, 검증 뒤 main이 바뀌지 않음, 중지 파일 없음(lib/worker.ts).
  • Worker는 data/*.json을 번들 모듈로 읽고 /data/*는 404로 검사한다. KV, R2, D1, Durable Object, Queue 바인딩은 없다.
  • 그리지 않은 것: 남아 있는 vercel.json(종료됨), 대기 상태의 Actions 배포 job, 회사 발굴(discover)의 세부 증명 경로.
  • 위키는 미니PC가 같은 자료로 만드는 파생본이며 웹(app/)은 lib/wiki.ts를 읽지 않는다.

build.mjs가 architecture.html을 만든다. 이미지는 같은 HTML을 화면 없이 캡처한 것이다.
