# 테스트를 어디까지 두는가

지원자가 서로 다른 조건으로 탐색해도 결과가 섞이지 않고, 바뀐 자료를 읽으며, 검증 실패를 성공으로 해석하지 않는 것이 우선입니다. 테스트 수나 줄 커버리지 목표는 두지 않습니다.

## 계층별 책임

| 계층 | 확인하는 실패 | 이 계층만으로 주장하지 않는 것 |
| --- | --- | --- |
| 순수 함수·계약 | 경력 0년과 미기재, 명시적 전체 직무, 직군 단어 충돌, JEV 경계값·응답 위조 | 실제 페이지의 요청 경계, 모델의 의미 정확도 |
| 제어한 비동기 실행 | A 읽기를 멈춘 사이 B가 완료되는 순서, 실패한 Promise의 회복 | 운영 환경의 모든 스케줄링 순서 |
| 전송 모의 | 여러 입력 중 호출 상한, 첫 오류 후 중단, 저장 실패 시 요청 차단, 오프라인 재평가의 입력 결속 | 실제 유료 API의 품질·가용성 |
| production HTTP | 동시 사용자 조건 분리, 파일 변경 후 본문·메타데이터 갱신, 오류 후 실제 내용 복구 | 클릭·키보드·스크롤·모든 화면의 시각적 품질 |
| 가상 데이터 검증 | 등록 가능한 3개 회사, 검색 조합, 비교 가능한/불가능한/누락된 인원, 근거 변경 시 읽기 연결 무효화 | 글자 수로 판단한 콘텐츠 품질 |

겹쳐 보여도 책임이 다른 검사는 남겼습니다. `revision-cache.test.ts`의 주입한 revision은 경쟁 순서를 정확하게 제어하고, `published-data.test.ts`는 실제 reader가 UTC 날짜를 revision에 넣었는지 확인합니다. 직무 우선순위 단위 검사는 규칙을, HTTP 검사는 그 규칙이 요청별 쿠키와 실제 결과에 적용되는지를 확인합니다.

예제 데이터 생성 결과를 같은 함수의 결과와 한 번 더 비교하던 검사는 제거했습니다. 저장된 스냅샷과의 비교로 재생성을 확인합니다. 안내 글의 최소 글자 수도 품질 기준으로 사용하지 않습니다. 읽기 연결은 비어 있지 않은지, 자기 자신이나 중복 링크가 아닌지, 실제 대상과 근거 변경에 맞게 해제되는지를 봅니다.

## 테스트가 결함을 잡는지 재현하기

```sh
pnpm test:sensitivity
```

[`check-test-sensitivity.mjs`](../scripts/check-test-sensitivity.mjs)는 임시 복사본에서 먼저 정상 테스트를 통과시킨 뒤 아래 변경을 하나씩 적용합니다. 체크아웃은 수정하지 않으며 키와 외부 API가 필요하지 않습니다. 변경을 잡지 못하면 명령이 실패합니다. 문법 오류·타임아웃·로드 실패는 성공적인 탐지로 계산하지 않습니다.

| 주입한 결함 | 검증 대상 |
| --- | --- |
| 오래된 요청이 현재 캐시를 무조건 제거 | revision 경쟁 상태 |
| 갱신 재시도 상한을 3회에서 1회로 축소 | 제한된 재시도 계약 |
| 연구 자료의 UTC 날짜 revision 고정 또는 한국 날짜로 변경 | 실제 published reader와 자정 경계 |
| `role=`를 미지정처럼 처리 | 명시적 전체 직무 |
| JEV의 세 차원 중 하나만 통과해도 승인 | 판정 집계 |
| confidence 0.75 경계를 제외 | 임계값 |
| 요약 결과에 발행 권한 부여 | 평가·발행 분리 |
| 배치의 호출 상한 무시 | 전송 수와 선택 순서 |
| 첫 전송 오류 후 다음 호출 계속 | 오류 후 중단 |
| 재평가 시 사례 해시 검사 생략 | 입력 결속 |
| 요청 전 실행 기록 저장 생략 | 저장과 요청 순서 |
| warm read 관측값 비교 제거 | 계측 검증의 유효성 |

2026-10-22 점검에서는 처음 선정한 12개 중 6개가 기존 테스트를 통과했습니다. 보강 후 12개 모두 탐지했고, UTC 대신 한국 날짜를 사용하는 결함까지 추가해 13개가 assertion 실패로 탐지되는지 검사합니다. **전체 프로그램의 mutation score나 무결함 보장이 아니라, 위 결함 목록에 대한 재현 결과입니다.** 변경 기준 문자열이 사라지면 실험도 실패하므로, 리팩터링 때 각 결함의 의미를 유지하며 수정해야 합니다.

SSR 계측은 시작 시 양성 대조, warm 요청의 파일 읽기 0회, 강제 자료 변경 후 실제 파일 읽기 관측을 함께 확인합니다. 계측 결과가 비었거나 warm 비교가 제거되어도 통과하는 경우를 별도 부정 대조로 막습니다. 이는 파일 읽기 회귀 검사이며 지연 시간 벤치마크가 아닙니다.

## 의도적으로 남긴 범위

운영 수집·발행 worker, 실제 모델 의미 평가, 브라우저의 모든 탐색 동작은 이 공개판의 자동 테스트 범위가 아닙니다. 브라우저 QA는 별도로 수행했지만 CI가 북마크·뒤로 가기·접근성을 전부 검증한다고 주장하지 않습니다. 새 테스트는 재현할 사용자 실패나 계약 위반이 있을 때 추가하고, 같은 층에서 같은 입력·실패를 확인하는 검사는 합칩니다.
